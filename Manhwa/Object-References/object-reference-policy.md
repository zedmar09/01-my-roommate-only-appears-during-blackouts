# Object Reference Policy

## When An Object Needs A Canonical

Create or reuse an object canonical when a recurring object:
- appears in multiple strips and visual identity matters
- carries a plot clue
- changes state in a precise sequence
- produces dialogue/device text/SFX
- has supernatural effect language that must remain consistent

## Naming Rule — Absolute

Name reusable object references by object identity only. Never prefix them with chapter numbers.

Examples:
- `smart-speaker-canonical-reference-prompt.md`
- `tv-canonical-reference-prompt.md`
- `refrigerator-canonical-reference-prompt.md`

If the same object returns in a later chapter, reuse the existing canonical.

## Authority

Object canonicals control body proportions, bezel/handles/cords/displays, materials, neutral state, and approved visual state/effect vocabulary.

The current strip script controls exact current text and exact story state. Reference-sheet sample text demonstrates effect styling only and never overwrites locked strip wording.

## Attachment Discipline

Attach an object canonical only when the object is visible or its exact state/design is story-critical. Do not attach every object reference to every strip.

## Effect-State Rule

Different objects may share a supernatural family while manifesting it differently.

Established reusable manifestations:
- smart speaker helpful communication = clean, restrained, audio-focused cyan-white signal
- TV hostile state = broad full-screen signal/broadcast hijack language
- refrigerator hostile state = embedded narrow-display diagnostic/identity-lock intrusion

Never swap these object-specific manifestations.
